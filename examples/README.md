# examples：业务样例需求

状态：本目录仅有样例设计，尚无可执行示例。现有固定沙箱 fixture 位于 `poc/sandbox/`，不能替代以下真实模型驱动 Agent 样例。

每个样例必须提交无敏感数据的 fixture、固定 Agent 版本/摘要、输入 schema、工具/网络/文件策略、资源/步数/时间/费用上限、执行方式、断言和可重现证据。不存放真实用户工作区或生产站点数据。

| 编号 | 阶段/规划目录 | 输入与步骤 | 产物与验收 |
|---|---|---|---|
| EX-01 | M1 / server-analysis | 内置文档/代码 fixture；真实模型生成 Python/Shell 分析，在服务端沙箱执行；浏览器读取本地测试 HTML 提取固定字段 | JSON 报告、可阅读摘要、浏览器截图；数值/字段对 fixture 断言，截图可读取，记录模型与工具步骤 |
| EX-02 | M2 / local-workspace | 指定本机测试目录只读挂载；Agent 分析文件并在独立输出目录生成报告 | 输入目录不变，报告符合已知样例；越界、符号链接逃逸和尝试修改输入均被实际阻止 |
| EX-03 | M2 / edge-summary | 受管 Linux 在线读取合成站点数据；仅允许汇总字段上传；断网后按有效授权处理 | 汇总校验通过；中央日志/产物不含原始数据；过期授权不发起新工具操作，重连可对账 |

## 一致性与负例

三个样例使用同一任务 API、Web 和 Runner 协议，仅池、能力和数据策略不同。固定 fixture 的断言为确定性要求，模型自然语言输出不要求字面完全一致。记录模型版本、提示/Agent 版本、最大输出和上游配额，避免不可复现的“看起来成功”。

每个样例至少包含无权限输入、输出超限、取消和工具超时。浏览器使用隔离会话及本地 fixture，外部只读站点若后续加入需明确域名；首批不提交真实表单、不登录个人账号、不修改第三方数据。

Demo 只验证 API/交互路径，模拟模型只用于故障注入；EX-01 至 EX-03 的正式成功必须包含真实模型及真实隔离执行证据。未安装浏览器或没有沙箱宿主时，标记未运行而非跳过后通过。
