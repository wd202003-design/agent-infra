# MVP 范围与验收

## 目标与适用范围

验证统一平台可以可靠地将 Agent 任务调度至服务器、本机与在线边缘节点，并控制模型访问和费用。
架构保留 1k+ 执行扩展能力，第一期以 100 个真实并行任务验收。
如果业务明确要求 1,000 个真实并行任务，必须单独调整上线门槛并用代表负载验证。

## 用户闭环

1. 选择已注册、固定版本的 Agent，输入参数，选择执行池。
2. 提交任务，取得持久化任务 ID。
3. 查看排队原因、运行状态、日志与产物。
4. 申请取消，确认停止后进入取消终态。
5. 查看模型调用量及估算费用，区分估算值与上游对账值。

管理员可注册和吊销节点、配置标签与槽位、暂停领取新任务、配置模型上游。
MVP 为单组织，包含管理员和使用者两个角色。

## 范围

| 领域 | MVP | 后续 |
|---|---|---|
| Agent | 一种 Runtime，单 Agent 有限步骤 | 多 Runtime、动态多 Agent、复杂 DAG |
| 服务端 | Linux 容器执行 | 微虚拟机、弹性扩容 |
| 本机 | 一种目标 OS，显式绑定工作区 | 多平台、桌面自动化 |
| 边缘 | 受管 Linux，在线中央调度 | 离线自治、站点控制面 |
| 调度 | 池、标签、槽位、节点暂停 | 抢占、多维优化 |
| 模型 | 一网关，1～2 个上游 | 动态质量路由 |
| 限制 | 上游并发、RPM/TPM、任务预算 | 多租户公平排队 |
| 恢复 | 安全重试、关键步骤检查点 | 任意步骤跨节点恢复 |
| 数据 | PostgreSQL、对象存储 | 跨区域复制、商业结算 |

不在第一期引入 GPU 调度、KubeEdge、独立消息总线和多级站点调度器，除非 ADR 证明必要。

## 规模验收

| 指标 | 目标 | 方法与条件 |
|---|---|---|
| 真实节点 | 10～20 | 至少覆盖三类执行位置 |
| 真实并行任务 | 100 | 运行代表业务负载，记录同时执行数与成功率 |
| 活跃任务 | 1,000 | 执行、排队、等待之和，不等同于并行执行 |
| Runner 连接 | 1,000 个模拟节点 | 测试心跳、断连、重连及状态对账 |
| 任务领取延迟 | P95 ≤ 3 秒 | 从调度就绪至领取；合格节点空闲且满足配额 |
| 稳定性 | 连续 24 小时 | 已确认提交的任务无丢失，故障后状态可恢复 |
| LLM 并发 | 按账户真实额度 | 单独记录并发、RPM、TPM、429 和等待时间 |

每次验收固定并记录机器配置、代码版本、模型、上下文及输出规模、工具步骤数、
任务时长、网关配额、样本数、错误率和费用。模拟模型用于故障注入，不能替代真实业务验收。
领取延迟同时报告端到端排队时间，避免只报告排除限流后的延迟。

## 可靠性验收

| 注入场景 | 必须满足 |
|---|---|
| 重复提交 | 相同幂等键与输入只创建一个任务；不同输入冲突 |
| Runner 崩溃 | 租约到期后离开正常运行态；依据任务副作用策略处理 |
| 旧 Runner 重连 | 旧执行代次不得更新当前结果；事件可审计 |
| 模型 429 | 有界指数退避及抖动；存在重试和等待上限 |
| 额度不足 | 显示等待原因，队列有容量与等待期限 |
| 外部写操作超时 | 进入待核对状态，不盲目重试 |
| 用户取消 | 先取消中；确认执行已停止后才取消完成 |
| 控制服务重启 | 已接受任务与关键状态恢复，不丢失队列依据 |
| 节点断网 | 不领取新任务；授权过期不得发起新工具操作 |

## 三个业务样例

- 服务端批量分析文档或代码并生成报告：调度、模型额度、产物。
- 本机只读分析指定工作区：节点绑定、工作区约束、本地产物。
- 边缘读取测试站点数据并上传允许的摘要：数据位置、断网、事件回传。

MVP 默认使用只读、可重复计算或独立产物生成任务。
生产部署、删除、数据库写入在审批和幂等机制完善前不开放。

## 完成定义

三个样例使用同一套 API、Web 与 Runner 协议；功能和故障用例通过；
提交容量测试报告、恢复操作说明与已知限制。
仅文档完成、模拟连接通过或空任务吞吐达标不构成 MVP 完成。
