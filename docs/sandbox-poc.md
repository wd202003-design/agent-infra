# 沙箱 PoC 验收矩阵

## 两阶段

1. 工具执行面：固定 fixture 验证代码、Shell、浏览器和清理。脚本已提供，真实集成待运行。
2. Agent 闭环：模型选择工具 → 权限校验 → 执行 → 回传 → 继续或终止。Runtime 与任务引擎随后确定。

## 验收项目

| 项目 | 证据 | 当前状态 |
|---|---|---|
| Shell、Python | 正确退出状态、产物内容 | 脚本已提供，未真实运行 |
| 浏览器 | 本地页面点击、截图 | 脚本已提供，未真实运行 |
| 命令超时/中断 | 查询命令已停止且非零退出 | 脚本已提供，未真实运行 |
| 沙箱删除 | 管理 API 不存在、宿主无残留容器/进程 | API 检查已提供；宿主人工核验待执行 |
| 进程树 | 派生子进程后取消，无孤儿进程 | 待补充 fixture |
| 文件隔离 | A/B 两任务互不可读；宿主哨兵文件不可读 | 待补充受控 fixture |
| 网络隔离 | 从宿主确认监听端点可达，从沙箱确认被拒绝；覆盖 IP/DNS/IPv6/重定向 | 待部署受控测试端点 |
| 浏览器副作用 | 测试站点提交后断连，记录未知结果且不自动重放 | 待补充测试站点 |
| 创建响应丢失 | 按 run_id 对账，无盲目重复创建 | 单元分支通过，真实故障待注入 |
| 节点/Server 故障 | TTL、恢复、孤儿沙箱盘点 | 待真实故障注入 |

网络测试不能仅以连接失败判断隔离：应证明目标原本可达、记录策略和执行侧证据。
不得针对生产管理网或真实客户系统进行探测，使用测试 VM 中专设的端点和哨兵数据。

## Agent 阶段的契约草案

工具请求字段：task_id、attempt_id、execution_epoch、sandbox_id、operation_id、tool、arguments、deadline。
工具结果字段：operation_id、status、exit_code、artifact_refs、error_class、outcome_known。
本 PoC 尚未实现此协议、审批或业务幂等。浏览器提交、外部命令写入等结果未知时进入 needs_review。
Shell/代码可任意联网，逐次工具授权不能代替沙箱网络限制；平台长期密钥不进入任务环境。

## 容量

分开测纯代码、Shell、浏览器、混合负载。先单任务，再逐级增加至目标 100 并行。
分别记录 Agent、沙箱、浏览器与 LLM 并发，冷/热启动 P95、峰值内存、CPU、进程/文件描述符、回收延迟与失败率。
100 混合任务不代表 100 浏览器任务；1,000 模拟连接不代表 1,000 执行。
首次单任务通过前不发布容量结论。
