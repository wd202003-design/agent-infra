# 实施路线

当前阶段为 M1 前置的沙箱 PoC。清单未勾选项均未实现，不以日历时间代替验收。

## M0：项目初始化

- [x] 建立私有仓库、README、MVP 与架构文档。
- [x] 明确组件边界、容量口径及可靠性底线。
- [x] 建立目录骨架、贡献规范和 ADR 模板。

## M1 前置：动态执行沙箱

- [x] 记录 OpenSandbox PoC 决策和隔离边界。
- [x] 提供代码、Shell、浏览器固定 fixture 与生命周期故障单元测试。
- [ ] 在 Linux Docker 测试 VM 上构建镜像并运行真实执行链路。
- [ ] 验证网络/文件隔离、进程树终止、宿主回收及副作用未知场景。
- [ ] 接入模型驱动工具循环，再比较任务引擎。

## M1：单任务闭环

- [ ] 通过 ADR 确定实现语言、工作流引擎、Runtime 与网关。
- [ ] 完成任务/节点/事件协议与数据库迁移。
- [ ] 提供一个可启动的控制服务和 Runner。
- [ ] 支持注册 Agent、提交、领取、执行、模型调用、日志及结果。
- [ ] 实现最小 Web 提交及结果页。
- [ ] 提供一个只读任务与开发环境启动说明。

退出条件：从干净环境按 README 启动，Web 提交任务并通过真实模型返回产物。

## M2：三类节点

- [ ] 引入节点身份、目标池、能力标签、槽位与暂停领取。
- [ ] 实现一种本机 OS 的工作区限制。
- [ ] 接入受管 Linux 边缘节点及数据上传策略。
- [ ] 三个验收样例使用相同协议。

退出条件：服务器、本机与在线边缘分别成功完成代表任务，越权资源访问被实际拦截。

## M3：故障与额度

- [ ] 持久化提交幂等、租约及执行代次。
- [ ] 实现有界重试、未知副作用核对、取消与停止确认。
- [ ] 模型额度池、并发/RPM/TPM 限制与任务预算。
- [ ] 支持断网重连、服务重启恢复、日志去重及结果对账。
- [ ] 编写并执行 MVP 故障注入用例。

退出条件：故障验收全部通过，未出现旧代次覆盖结果、已接受任务丢失或未知写操作盲目重试。

## M4：容量与交付

- [ ] 10～20 个真实节点上的 100 任务并行。
- [ ] 1,000 活跃任务与 1,000 模拟 Runner 测试，分别报告。
- [ ] 完成 24 小时稳定性测试及领取延迟统计。
- [ ] 提交负载定义、测试结果、瓶颈、费用和已知限制。
- [ ] 补齐备份恢复、凭证吊销、节点排障与发布回退操作说明。

退出条件：达到 docs/mvp.md 的验收口径；未达到项明确阻断交付或正式调整范围。

## 后续候选

1k+ 真实执行、多租户公平排队、边缘离线自治、多 Runtime、跨节点恢复、
微虚拟机隔离、自建推理服务。按业务证据排序，不自动纳入 MVP。
