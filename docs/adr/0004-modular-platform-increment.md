# 0004：正式模块首轮实现边界

- 状态：接受本轮实现范围；生产就绪和完整 M1–M4 验收尚未通过。
- 日期：2026-10-11。

## 决策

正式模块首轮采用 Python 3.12 / FastAPI / PostgreSQL，与独立 Python Runner 通过版本化 HTTP 长轮询式领取和心跳协作。本机首轮目标为 Linux；Windows/macOS 支持未承诺。Python 复用沙箱 SDK，避免首轮引入跨语言契约重复维护。

控制面作为唯一状态入口；任务、事件、执行代次和模型预留在 PostgreSQL 事务中提交。首轮用数据库持久队列协调，不自动重试 attempt；全局事务级 advisory lock 串行化状态变更，优先保证正确性。该实现不是最终工作流引擎：Hatchet/Temporal 的选型与接入仍待 PoC，无外部引擎双写，因此本轮不需要伪造 outbox 消费者。吞吐目标未验证，后续须以行级调度事务/引擎替换粗粒度锁。

Runtime 暂采用自有有限 JSON 工具循环，仅支持固定系统模板、模型响应中的 python/shell/browser 或 final 动作；不运行上传的 Runtime 插件。通过控制面的 OpenAI-compatible HTTP 适配访问管理员配置的模型网关，上游密钥不交给 Runner 或任务。LiteLLM/Bifrost 与第三方 Runtime 仍待决；本轮适配不等于完成其选型。

管理员预配置用户哈希令牌与节点引导信息；节点凭证独立生成且可吊销。首次使用仅支持管理员批准的池、能力、单节点单槽位及无宿主挂载策略。多槽位、本机工作区、边缘上传政策、凭证自动轮换与第三方登录后续交付，不通过自报能力开放。

## 安全和恢复

所有正式任务需固定 Agent 版本、执行池、有限时长/步数和 token 额度。token 预算为保守预留的用量限制，不宣称硬货币预算；未知模型结果不释放预留，不自动重发。共享额度在数据库中全局协调。

Runner 的领取响应先持久化到本地 journal 再执行；重启发现未结束 attempt 时上报待核对，不重放工具操作。领取响应丢失通过同一 claim_id 返回同授权。租约过期转 needs_review，不自动重新派发。沙箱清理仅管理 API 确认而无宿主证据时，真实后端结果仍需核对，禁止标记已验证成功。Cube 的无界 SDK 输出问题解决前，正式 Runner 禁用该后端；开发 PoC 保持不变。

模型产生的源码仅在受管沙箱中执行。Demo 明确模拟；不存在宿主执行降级。浏览器仅执行隔离沙箱内程序，不使用操作者浏览器会话。产物首轮为受限 JSON 结果，存 PostgreSQL 并经鉴权下载；对象存储/任意文件产物尚待实现。

## 代价与后续

本轮将目录占位变为可运行模块，但不等于所有 37 项需求完成。SQLite 仅通过显式测试配置运行相同服务逻辑，不能作为正式部署后端，也不能替代 PostgreSQL CI。真实沙箱、模型、三类真实节点、备份恢复和容量需另有证据。状态/API 只冻结已实现 v1 子集，ADR 0003 未实现部分继续提议。
