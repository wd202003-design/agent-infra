# 0003：正式平台契约与状态职责草案

- 状态：提议，尚未接受或实现。
- 日期：2026-10-11。
- 关联：[需求索引](../requirements.md)、[契约草案](../../contracts/README.md)。

## 背景

开发版验证了单进程生命周期，但正式 Runner、工作流引擎和模型循环尚未接入。按目录分工之前，需要避免各模块分别定义状态、重试与取消语义。

## 提议

正式接口使用版本化命名空间，与现有 `/api/*` 开发接口区分；具体 wire schema 和传输选型在实现前评审。控制面为外部任务状态提供唯一写入入口，工作流适配器把引擎决策转换为带版本检查的状态命令。引擎负责协调，不能绕过入口独立修改业务状态或重复安排重试。

数据库接受事务与引擎启动通过 outbox 或等效机制连接；每次执行采用独立 attempt 和递增 epoch。完成执行、停止确认、沙箱回收分别记录；不以租约过期、SDK 关闭或管理 API 404 单独证明宿主执行已停止。对外状态投影需遵守取消和未知副作用约束。

## 备选与代价

- 直接暴露工作流引擎状态：集成较少，但对外 API 与引擎耦合，难承载人工核对和节点清理证据。
- 数据库与引擎各自重试：暂不采用，可能重复执行和产生互相矛盾的状态。
- 提议方案：需要事件去重、outbox 清理和对账任务；不能宣称跨系统 exactly-once。

## 接受前必须验证

选定一个引擎，分别在数据库提交后、引擎调用前后、领取响应丢失和结果提交后注入崩溃；证明无已接受任务丢失、无重复有效执行授权、旧代次不能覆盖结果。评审契约、鉴权、取消竞态与迁移计划后更新本 ADR 状态。

本提议不选择语言、Runtime、网关、Runner 传输协议或生产沙箱，也不修改 ADR 0002 的开发版行为。
