# 0002：先交付可运行的单进程任务执行开发版

- 状态：接受（开发阶段范围）
- 日期：2026-10-10
- 背景：需要在 CubeSandbox 评估后继续推进任务服务，且真实沙箱测试宿主尚未就绪。

## 决策

采用 Python 3.12、FastAPI 与 SQLite 实现一个可运行的开发控制服务。
Python 复用两个沙箱 SDK，SQLite 支持本机零外部数据库启动，并验证提交幂等、状态事务及重启行为。
此选择仅适用于 devserver，不决定正式控制面/Runner 的语言，也不替代目标 PostgreSQL、Hatchet/Temporal。
使用一个服务进程和一个后台执行器，并用进程文件锁强制此约束。

执行后端通过 create / execute / destroy 接口分离，提供 demo / opensandbox / cubesandbox。
Demo 必须显式标记模拟，不能在宿主执行源码或伪装成沙箱成功。
真实后端不开启失败自动重试、快照回滚或出站网络；沙箱创建归属写入任务 ID 和 metadata。

## 恢复与责任

数据库是本开发版任务状态权威。排队任务恢复，运行中任务重启后进入 needs_review，不自动重放。
任务创建、领取与状态事件使用事务。每次领取递增 epoch，终态更新检查 epoch。
取消先记录请求，SDK 调用结束后核对回收再进入终态。暂不声称实现即时中断或分布式租约。

## 代价与迁移

不能多进程横向扩展；没有正式 Runner、资源调度、模型循环、预算、多租户或对象存储。
正式阶段使用 PostgreSQL 迁移与选定工作流引擎接管任务协调，保留公开任务契约和沙箱适配边界。
开发 SQLite 不作为生产数据库，也不默认承诺自动迁移现有测试任务。
在平台化以前先完成真实沙箱、认证与隔离验收；Cube SDK 输出累积问题必须解决。
