# 部署、发布、样例与验收

适用：DP-01～06、EX-01～03、AT-01～10。以下是目标部署/验收方案；当前 [Compose](../../deploy/compose.yaml) 仅为单机集成环境。

## 拓扑与配置

| 区域 | 服务/数量基线 | 访问边界 |
|---|---|---|
| 接入区 | TLS 反向代理、静态 Web；控制面至少2实例 | 用户只访问 HTTPS API；无数据库/沙箱管理端公开端口 |
| 控制区 | 控制面、model-access、Temporal Worker；Temporal 按其受支持 HA 拓扑独立部署 | Worker/控制面到 PG/Temporal/对象存储/批准模型上游；网络策略与服务身份同时限制 |
| 状态区 | PG 主库 + 独立宿主同步备库；加密 WAL/备份；私有对象存储 | 业务、Temporal persistence 使用分离账户/数据库；备库故障时不能悄悄降级同步持久性 |
| 执行区 | server/local/受管 Linux edge Runner，沙箱管理面及只读 verifier | Runner 主动出站；不可信沙箱不能访问管理服务、node token 或控制面管理 API |

默认部署在 Linux VM；PVE 中须跨物理宿主放置冗余状态服务，不能把同一宿主上的两个 VM 当成故障隔离。Cube 测试 VM 先验证嵌套 KVM/文件系统/网络，不调整生产 PVE 宿主来绕过条件。

发布清单必须包含 Git SHA、schema/协议/Runtime 版本、所有第三方组件版本、镜像 digest、批准模板/策略摘要、资源规格、模型与价格/配额配置、证书签发者和到期时间。实际 secret 只引用秘密路径，不写入清单。默认配置取 D1 defaults，启动时按 schema 校验；占位 endpoint、缺失证书或未知能力禁止开启对应功能。

## 就绪、观测和处置

live 仅表示进程可响应；ready 校验 schema/数据库可用、当前 coordinator 依赖与策略加载。模型依赖不可用只阻断模型任务/步骤，不能让固定工具任务假报模型可用。依赖抖动不能通过频繁重启丢失 journal。

| 指标/告警门槛（初始值） | 处置 |
|---|---|
| outbox 最老未投递 >30秒或持续失败 | 检查 Temporal/dispatcher；停止新执行授权，保留已接受任务 |
| 心跳 >15秒未见、租约过期 | 节点标记疑似失联；到期停新步骤，不自动重派未知任务 |
| needs_review 新增、孤儿资源 >0 | 关联 task/attempt/sandbox 和账目，按证据核对；不删除归属记录 |
| 配额未知请求 >60秒、余额/预留异常 | 暂停对应池新请求，核对上游用量，禁止换 key 规避 |
| WAL/日志/数据库磁盘 >80%，或预计2小时耗尽 | 暂停新领取、压制普通日志；保留关键停止记录，扩容或按已批准保留策略清理 |
| 合格领取 P95 >3秒持续5分钟 | 对照槽位/资源/配额及SQL锁等待，不能只隐藏不合格样本 |
| TLS/节点轮换失败或证书不足7天 | 运维轮换、校验重叠窗口；到期默认拒绝，不关闭 TLS 校验 |

指标标签不放 prompt、文件名、用户原始输入和 token；task/attempt/request ID 用结构化受限日志关联。管理审计不可被普通应用账户删除；另送独立存储以检测宿主篡改。测试侧保留图表和原始计数，不能只截图最后成功页面。

## 备份与恢复

PG 持续 WAL 归档，日全备，保留30天；目标灾难恢复 RPO≤5分钟、RTO≤2小时。同步备库承担单主机故障下已提交记录不丢；整站灾难的备份 RPO 与常规故障零丢失验收分别报告，不能把备份窗口当作正常丢任务的许可。业务 PG、Temporal persistence、对象内容和删除账本都纳入恢复清单。

每月在隔离环境恢复到指定时间点：先恢复状态/对象与凭证撤销及删除账本，禁止 Runner 接入；扫描在途 attempt 和 outbox，与 Temporal/沙箱管理面核对。恢复前有效的 node/task capability 全部失效并重新签发；旧节点不能凭备份回退后的 token 重新获得执行权。对账完成再开放只读，最后开放新提交；未知执行保留 needs_review。

验证任务计数/幂等键、对象摘要、账本余额、审计链及删除请求已重放；演练记录真实 RPO/RTO 和缺失范围。对象存储的版本/复制能力必须实测，不能假设 PostgreSQL 备份包含对象内容。备份密钥另行保管；仅有加密备份而丢密钥不算可恢复。

## 发布与回退

顺序：锁定清单 → 备份/恢复点 → expand migration → 兼容控制面 → 新 Worker/Runner 灰度 → 样例/故障检查 → 逐池开启新任务 → 排空旧版本。每个任务固定 coordinator/protocol/runtime/policy 版本。Worker 升级要用支持的版本路由或重放兼容测试，不能让不兼容 Workflow history 在新代码重放。

回退停止新功能/任务准入，排空或核对在途工作，部署兼容旧版；不要回滚数据库到更早快照后直接恢复调度，否则可能重放外部副作用。schema contract/数据迁移失败时冻结写入口，按协调文档修复或隔离恢复；未验证的 down migration 不自动运行。

## 三个真实业务验收

| 样例 | fixture/边界 | 必须证据 |
|---|---|---|
| EX-01 服务端 | 合成数列与代码 fixture；真实模型产生代码/Shell步骤，隔离浏览器读取本地 HTML；JSON摘要/PNG/报告 | 确定性 count/sum/字段断言、真实模型用量、工具记录、对象 SHA-256、宿主回收；不只检查自然语言 |
| EX-02 本机 | 受管 Linux 只读工作区快照，独立输出目录；私有内容不发送中央模型，模型仅接收批准 fixture/摘要 | 输入前后摘要相同、越根/符号链接/修改输入被拒、实际本地报告；未批准内容在模型/日志/产物出口缺席 |
| EX-03 边缘 | 合成站点原始数据由可信固定程序聚合，Agent只访问摘要；注入断网/重连 | 出口 schema/大小强制、原始数据不入中央、到期无新工具、journal补传无重放、合法摘要校验 |

EX-02/03 必须真实使用 Linux 节点和数据策略；仅改变 node.location 标签不算完成。三个样例使用同一 API/Web/Runner 协议，fixtures 不含生产数据；每个都执行取消、输出超限、授权失败和工具超时负例。

## AT-10 负载冻结

默认验收协议如下，任何变更先更新设计/报告，不在失败后调整门槛。

- 10～20 个真实节点，至少 server/local/edge 各2个；记录实际 CPU/内存/可用槽位。100个1CPU/2GiB沙箱至少预留100CPU/200GiB可分配资源，另加宿主/浏览器/平台余量；初始规划30%余量只是容量预算，不是实测结论。
- 代码60%、Shell20%、浏览器20%；代表任务持续20～60秒、最多4步，输入/输出规模随 fixture 固定。每类至少100个真实模型驱动样本，并单列无模型工具压力结果；不能用模拟模型结果代替业务样例。
- 真实执行压力阶段持续30分钟：稳定段同时执行数达到100（按工具/沙箱执行区间而非 queued/waiting），完成样本≥3000，非故障注入任务成功率≥99%，报告超时/未知/失败全量分母。上游额度不足时该目标记未达到，不偷偷改为模拟模型。
- 管理负载另测1,000活跃任务，按所有未完成状态细分；模拟连接另测1,000 Runner，心跳/断开/重连混合30分钟，不能计入真实节点或执行数。
- 合格任务 ready→claim 的P95≤3秒；同时提供整体排队时延、合格条件、被排除样本及最长等待，避免仅报易通过子集。
- 24小时持续混合运行，累计完成≥10000任务，至少包含一次上述30分钟100并行窗口；其余时段可用较低并行，报告真实曲线。常规提交零丢失、旧代次覆盖零、未知写自动重放零、停止/回收错误终态零，残留资源全部解释并核对。
- 单独注入每项AT-01～09故障至少3次；基线成功率不混入主动故障，但故障样本必须全部按预期状态收敛，不能删除失败数据。真实模型并发/RPM/TPM/429、等待、token和费用单列。

执行前固定机器清单、模型/配额、费用上限及终止阈值；模型/云资源不足时停止并记录未运行或未达到。设计默认值不是运行昂贵测试的实际调用，也不构成测量结果。
