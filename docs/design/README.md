## 不变约束

1. 控制面是业务状态权威；Temporal 发幂等命令，不直接改业务表。节点、SDK、网关不分别重试整项任务。
2. 提交成功必须可恢复；旧 epoch 不能更新结果；取消不等于回滚；租约到期不等于进程停止。
3. 文件、网络、工具权限由受管执行边界强制；未知外部写不自动重放。
4. 100 个真实并行任务、1,000 活跃任务、1,000 模拟连接和模型并发分别验收。
5. 默认不允许沙箱出站和宿主挂载；模型上游长期凭证只在控制面；秘密不进入日志、Workflow history 或产物。

## 完整性定义

所有 37 项需求均有设计位置与验收映射；关键组件有决策、操作接口有字段/幂等/权限、状态和外部副作用有失败路径、限额及保留/恢复目标有数值，升级有迁移与回退策略。因此 D1 可作为后续编码和评审基线。

保留为部署输入的只有实际 endpoint、证书/秘密、批准的路径/网段、节点清单、上游模型与价格表、镜像/组件版本及 digest。它们须由发布清单记录，不使用占位符上线。配置默认值的变更需要版本化策略；不得把真实测试失败改写为降低门槛。

## 实现增量顺序

| 增量 | 交付物 | 必须完成的验证 |
|---|---|---|
| I1 | 规范化表、next 协议模型、节点注册/轮换、策略/能力准入 | 迁移、版本拒绝、令牌过期/吊销及池/工作区越权 |
| I2 | Temporal/outbox/幂等状态命令、行级槽位与安全重试 | DB 与引擎的五个故障窗口、重放不重复授权 |
| I3 | 沙箱 stop/inspect、宿主证明、事件 WAL、只读工作区/边缘摘要 | 真代码/Shell/浏览器、网络/文件/输出洪泛、失联和回收 |
| I4 | 对象存储、费用账本、网关两上游与完整 UI | 用量未知、上传替换、越权下载、费用/游标/认证恢复 |
| I5 | 三个真实样例、恢复演练、100 并行/24h 报告 | AT-01～AT-10 全量门槛，无阻断缺陷 |

I1/I2 可在集成环境推进；I3 的真隔离验收是开放真实 Agent 动态代码入口的前提。当前 PR 合并的是完整设计与已有首轮实现，未实现的增量仍按 [实现清单](../implementation-status.md) 管理。
