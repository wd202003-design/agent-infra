# runner：统一执行节点需求

状态：已有独立 Python Runner，`python -m runner` 启动；支持单槽位主动领取、journal、续租与有限 Agent 循环。当前缺口见 [实现状态](../docs/implementation-status.md)。协议依赖 [contracts](../contracts/README.md)，执行生命周期见 [契约草案](../contracts/task-lifecycle.md)。

## 输入、输出与职责

Runner 使用独立节点身份主动连接控制面，接收带 attempt/epoch、租约、Agent 摘要、策略和限额的执行授权。负责沙箱生命周期、受控工具入口、心跳、状态和日志回传。返回执行结果、停止证据、清理证据及允许上传的产物；不拥有任务重试决策权。

规划 identity、leases、executor、sandbox、events、reconcile 子模块。平台选节点/池，沙箱后端负责自身节点内部或集群内部的具体安置；CubeMaster 的安置不替代平台任务权限与调度。

## 需求与验收

| 编号 | 阶段 | 设计要求 | 验收条件 |
|---|---|---|---|
| RN-01 | M1 基础 / M2 节点 | 短期引导注册、独立凭证轮换/吊销，主动出站连接，能力握手 | 无需本机入站端口；吊销节点不能领取/续租；版本不兼容拒绝执行 |
| RN-02 | M1 基础 / M3 故障 | 领取和续租绑定 attempt/epoch；重启核对本地资源归属；不私自恢复执行 | 丢失领取响应不创建第二实例；过期授权不发起新工具步骤；旧结果被隔离审计 |
| RN-03 | M1 | 每个 attempt 独立工作区和沙箱；资源、文件、网络、工具权限在模型外强制 | 访问越界路径、元数据地址、私网及未授权 IPv4/IPv6 出站被拒绝；资源超限不拖垮宿主 |
| RN-04 | M1 | 支持动态代码、Shell、浏览器；统一超时、输出限制、退出结果和停止接口 | 三类真实任务运行；输出洪泛在接收端受限；浏览器使用任务独立会话 |
| RN-05 | M1 基础 / M3 故障 | 取消进程树与会话、销毁沙箱、核对宿主；TTL 和孤儿扫描补偿 | 子进程不残留；管理面失联不报告 cancelled；未知资源归属可对账 |
| RN-06 | M2 / M3 | 有界本地事件缓冲、断网补传、产物摘要和上传策略 | 断线重连可去重补传；缓冲满有可见标记并按策略暂停，不无限占盘；关键状态不得静默丢弃 |
| RN-07 | M2 | server/local/edge 同协议；工作区挂载、信任等级与数据上传策略区别处理 | 本机只读工作区不能逃逸；边缘仅上传批准摘要；无离线自治领取 |

## 沙箱适配契约

| 操作 | 预期输入/输出 | 异常处理 |
|---|---|---|
| create | attempt 归属、可信模板/镜像、资源与策略 → sandbox_id | 发出请求前保存创建意图；响应未知按归属查找，不盲目重复创建 |
| execute | 授权工具、限额 → 有界 stdout/stderr、退出码、产物清单 | 不能在 Runner 宿主执行输入；超时进入停止/核对流程 |
| stop | sandbox_id、epoch → 进程树/浏览器停止证据 | 停止未知如实报告；不能只关闭 SDK 连接 |
| destroy / inspect | 资源归属 → 清理证据 | 管理面 404 加宿主验证；失败保留记录并交由对账补偿 |

这是正式能力要求；当前 devserver 只有 create/execute/destroy，取消等待 SDK 返回。不能把表中 stop/inspect 视作现有适配器已经具备。

OpenSandbox 为 PoC 基线；CubeSandbox 为服务端候选。先验证模板、权限、网络、资源上限和回收。Cube SDK 输出在返回前累积的问题必须通过流式/有界接收方案或隔离工作进程硬限额解决并压测；返回后截断不足以通过 RN-04。不得强制本机/边缘采用不具备宿主条件的后端。

## 失联与数据

租约失效停止发起新工具操作，并尽力停止已有执行；发出的外部请求仍可能完成，需重连核对。凭证/授权本地有效期检查不能代替控制面核验；时钟偏差处理须在协议选型中明确并测试。

非受管本机不能接收其他用户敏感任务或平台密钥。挂载仅由管理员批准的策略解析，禁止任意宿主路径、Docker socket、特权模式和日常浏览器登录态。工作区及原始边缘数据默认不上传，产物上传需显式规则。
