# v2 集成启动

先阅读 [实现与剩余差距](../docs/implementation-v2.md)。v2 默认关闭。生产不接受 SQLite，不自动降级到进程内协调；Temporal 不可达时 outbox 保留，任务不会被领取。

## 环境配置

沿用 `deploy/configure.py` 生成的 `.local/platform.env`，由密钥管理器补入以下值。不要提交该文件。

| 变量 | 要求 |
|---|---|
| AGENT_ENABLE_V2 | `1` |
| AGENT_V2_KEY | 32 随机字节的 base64url；胶囊和签名主密钥，需备份并设计轮换 |
| AGENT_USERS_JSON | v1 用户结构另加 `issued_at`、`expires_at` Unix 秒；最长 30 天 |
| AGENT_INTERNAL_TOKEN / AGENT_INTERNAL_TOKEN_SHA256 | 协调 worker 明文凭证 / 控制面哈希；与用户、节点凭证隔离 |
| AGENT_TEMPORAL_ADDRESS / NAMESPACE | 已部署的持久化 Temporal 地址 / 命名空间 |
| AGENT_INTERNAL_CONTROL_URL | 内部 TLS 控制面地址；不得公开内部路由 |
| AGENT_S3_BUCKET / ENDPOINT | 私有启用版本控制的桶；端点可省略使用 AWS |
| AWS_ACCESS_KEY_ID / SECRET_ACCESS_KEY / DEFAULT_REGION | 仅控制面/协调器可读；Runner 不持有管理存储凭证 |
| AGENT_VERIFIER_KEY | 独立 32 随机字节 base64url，仅控制面和独立验证服务持有 |
| AGENT_V2_MODEL_JSON | 固定上游配置，格式如下；不能下发到 Runner/guest |

模型配置字段：`url,key,model,quota_pool_id,price_version,currency,input_micro_per_million,output_micro_per_million`，可选 `parallel=2,rpm=20,tpm=200000`。价格单位为每百万 Token 的微货币；所有相同供应商额度的 key 必须使用相同 quota_pool_id。只有供应商合同明确保证 `X-Request-Executed: false` 的 429 未执行/未计费，才可以设置 `trusted_unexecuted_429=true`。

```bash
PYTHONPATH=control-plane:. python -m infra_control migrate
cd deploy
docker compose --env-file ../.local/platform.env -f compose.yaml -f compose.v2.yaml up --build -d
```

开发隔离网络可以显式配置 `AGENT_INTERNAL_DEVELOPMENT=1` 以使用 `http://control:8766`；生产必须使用 TLS 入口和网络 ACL。Temporal 生产连接要求 `AGENT_TEMPORAL_TLS=1`；可配置 `AGENT_TEMPORAL_CA`、`AGENT_TEMPORAL_CLIENT_CERT`、`AGENT_TEMPORAL_CLIENT_KEY`（均为容器内文件路径）、`AGENT_TEMPORAL_SERVER_NAME` 和 `AGENT_TEMPORAL_API_KEY`。将证书只读挂给 coordinator，不能挂给 Runner。

打开 `/v2.html` 用短期管理员凭证登录，先发布策略和 Agent 版本，或运行 `examples/bootstrap_v2.py`。提交任务后由 outbox 启动 workflow、内部 make_ready 命令允许领取。

## Runner

管理员从控制台签发注册票据，将 `AGENT_TICKET_ID`、`AGENT_TICKET_SECRET`、`AGENT_BACKEND=demo`、`AGENT_RUNNER_SLOTS=1` 写入权限 0600 的 `.local/node-v2.env`。

```bash
cd deploy
docker compose --env-file ../.local/platform.env -f compose.yaml -f compose.v2.yaml --profile runner-v2 up -d runner-v2
```

注册结果保存在 Runner 独占目录的 0600 WAL。每 12 小时轮换；响应丢失重发同 rotation_id；旧凭证超过 60 秒重叠期后失效需重新注册，不能无限恢复旧秘密。Demo 不执行源码、不调用模型。

真实 backend 另需 OpenSandbox 配置和 `AGENT_VERIFIER_URL`（HTTPS）、`AGENT_VERIFIER_TOKEN`。验证器独立部署，运行 `uvicorn runner.host_verifier:create_app --factory` 并配置 TLS。其 Docker socket、验证签名密钥不允许挂给 Runner/guest。管理员配置 `AGENT_DOCKER_SANDBOX_LABEL`、`AGENT_DOCKER_TASK_LABEL`，必须对应真实资源标签；task 标签为 `task_id:attempt_id`。当前严格策略要求无网络、非 root 和只读根文件系统；公共任务无挂载，私有/边缘任务只允许经验证的单个只读工作区快照挂载。宿主机不满足时拒绝执行。

## 存储与维护

S3 桶必须私有并开启 versioning，凭证只授权 staging/final 前缀的 Get/Put/Copy/Delete/List 版本权限。上传 URL 5 分钟、下载 URL 60 秒；普通签名 URL 在有效期内可重用。当前拒绝私有数据下载路径，因此不能宣传即时撤销的私有链接。

协调器分别运行 outbox 与删除/保留维护循环；一个已运行的协调器发生 Temporal RPC 故障时，删除循环仍继续。也可由独立部署作业调用维护入口，避免协调器冷启动依赖阻断维护：

```bash
PYTHONPATH=control-plane:. python -m infra_control.v2.maintenance retention
```

恢复演练必须先关闭入口、Runner、协调器，恢复 PostgreSQL/S3 后重放独立备份的删除账本，再运行 `restore-fence` 与 `delete-sweep`，重新签发用户和节点凭证。严禁直接开放旧备份：旧凭证/旧下载引用/已删除内容可能被恢复。具体备份存储、pgBackRest/WAL 归档和删除账本外部复制仍需部署落地，尚无 RPO/RTO 达标证据。

## D1 工作区与边缘数据配置

用户配置增加 `workspace_refs: ["records"]`；策略同样授权 workspace_refs 和 data_classes。注册票据选择 `owner`、`location=local|edge`、`workspace_refs`，且 backend 必须为 opensandbox。共享/其他所有者节点不会领取这些任务。

节点用管理员专属配置文件提供 `AGENT_WORKSPACES_JSON`（不是用户请求）：

```json
{
  "records": {
    "root": "/srv/approved-data/records",
    "owner": "alice",
    "data_class": "edge_summary",
    "summary": {
      "algorithm": "numeric-jsonl-v1",
      "columns": {"value": {"min": 0, "max": 100000}},
      "min_rows": 10
    }
  }
}
```

private 映射使用 `data_class=private`，不配置 summary。设置绝对路径 `AGENT_SNAPSHOT_ROOT=/srv/agent-snapshots`，Runner 和独立 verifier/OpenSandbox 宿主必须看到同一目录；不允许父子路径与输入重叠。原始工作区需由管理员冻结/只读管理；复制期间文件变更会拒绝快照，不能把它描述成跨所有文件的数据库事务快照。新快照只读挂到 guest `/workspace`，不把原始目录挂给动态 Agent。

private 只接受管理员发布的固定 program。输出存于 snapshot root 同级的 `private-results/<attempt_id>.json`（0600），Web 只显示固定完成提示；用户内容删除后 Runner 获取删除清单并确认本地擦除，中央队列在确认前保持 pending。删除工作依赖节点在线，失联必须告警/人工处理。

edge 输入为 JSONL；固定聚合只提取批准数字列，拒绝不合法/越范围/非有限值、过小样本、超大小、特殊文件/软硬链接。只读快照仅含 `summary.json`；控制面保存批准摘要、verifier 从实际挂载源计算其 digest，二者匹配后才开放模型。

## 硬预算配置

在模型配置中增加 `billing_bound`，必须由管理员对真实模型/模板/tokenizer/供应商计费合同审核后填写，不能复制测试 fixture 作为生产证明：

- `algorithm="utf8-byte-upper-bound-v1"`：供应商 tokenizer 必须具有已验证的 byte-fallback 上界；`per_message_overhead` 和 `request_overhead` 是该模板的保守 Token 上界。
- `model`、`price_version` 与路由一致；`evidence_ref` 指向审核证据，`approved_by` 标记审批者，`valid_until` 是期限的 Unix 秒。
- `output_parameter` 为供应商实际保证的 `max_tokens` 或 `max_completion_tokens`。
- `output_limit_includes_all_billable_tokens=true`、`no_other_billable_items=true` 必须有合同依据，不能猜测。

硬预算任务固定这份记录及价格版本；价格/证明漂移或过期会拒绝新请求。实际用量超过边界时记录真实费用、任务进入 needs_review、路由被隔离；只有新的已审核路由配置可恢复调用。软预算不会变成硬预算。

升级前运行迁移到版本 003；不要在运行中的事务上手工重复执行 ALTER SQL。迁移入口已按 schema_version 跳过执行过的文件。v2 时间使用 RFC3339；Runner 客户端只对协议内已知时间字段转换，不修改任意用户 input 中同名字段。

## 受控互联网出站

默认禁网；公共任务可通过精确域名策略启用 HTTPS GET/HEAD 检查代理，完整配置与限制见 [egress.md](egress.md)。私有/边缘任务保持禁网。
