# control-plane：控制面设计需求

状态：正式模块尚未实现。现有单机试验在 `devserver/`；本目录采用何种语言、引擎、Runtime 和网关均须 ADR 决策。范围与顺序见 [需求索引](../docs/requirements.md)。

## 职责与模块

目标为模块化控制服务，先不拆多个业务微服务。规划 tasks（任务与状态入口）、agents（不可变版本注册）、nodes（身份与能力）、scheduler（资源匹配）、workflow（引擎适配）、model-access（网关集成）、audit（审计与查询）。

输入是认证用户的任务请求、Runner 心跳/结果及网关用量；输出是持久化任务、受限执行授权、可查询事件和产物引用。控制面不直接执行 Agent 源码、不启动用户宿主 Shell、不把上游密钥交给沙箱。

| CP-03 | M1 | 事务幂等提交，状态统一入口，outbox/等效引擎启动和恢复对账 | 提交成功后重启可查询；DB/引擎故障窗口不丢任务；同键异输入 409 |
| CP-04 | M1 基础 / M2 三类节点 | 按池、能力、槽位、可信等级和数据位置匹配；无资源有等待原因；排空不领取新任务 | 无匹配能力不误派；并发领取不超槽位；新任务不分给 draining 节点 |

| CP-06 | M1 | 接入一种有限 Agent 循环；固定 Runtime 与步骤策略 | 真实模型生成代码/命令/浏览器动作，至少完成一个工具步骤并生成校验产物；超步数/时间即停止 |
| CP-07 | M1 单任务 / M3 共享额度 | 统一网关，任务级授权，配额池、并发/RPM/TPM 和预算预留/核对 | 沙箱拿不到上游长期密钥；同池多 key 不放大额度；未知用量保留预留，共享配额不可用暂停新请求 |

## Agent 动态执行闭环

用户选择 Agent 版本和参数，控制面绑定策略、预算、执行池；Runtime 获取任务级模型授权。模型生成工具调用后，执行入口独立校验工具类型、参数、权限、授权期限及资源限额；Runner 在绑定该 attempt 的沙箱执行并返回有界输出，Runtime 继续到最终产物或停止条件。

Runtime 的实际部署位置在选型 ADR 决定。无论是否与 Runner 同机，动态用户代码必须在隔离环境运行；模型不能自行增加工具、出站地址、挂载目录、步骤数或预算。正式任务输入以 Agent 参数为主，开发版直接提交源码仅是测试入口。

每次运行必备上限：最大步骤、任务总时长、单工具时长、输出字节、资源配额、模型最大输出与费用预算。数值须在版本化 Agent/策略配置中明确；超限产生可解释事件，保留已用成本和部分产物，不伪装完整成功。

## 持久化与故障边界

目标表域包括 agents、tasks、attempts、nodes、events、artifacts、model_usage、audit、outbox。字段依据 [contracts](../contracts/README.md)；DDL 和索引在语言/引擎确定后补齐。任务状态事务、唯一幂等约束、条件更新和待发送记录是同一一致性边界。外部引擎/对象存储/网关失败由可恢复状态连接，禁止跨系统假定原子提交。

沙箱任务成功与产物可下载必须分别验证；上传失败记录可恢复原因，只有必需产物校验完成才报告任务成功。已发生但未确认的模型用量保留待核对账目，不因工作流重启释放全部预留。
